# 编程与计算机

先区分概念机制、编程方法、算法证明和项目实践。固定与内容有关的语言、运行环境和版本；不为展示覆盖面提供多语言实现。

## 实验环境是必备交付

程序教材必须配套读者可搭建、可自检、可重复运行的实验环境。环境属于教材交付的一部分，只列操作系统和语言版本不足以满足要求。

按教学目标确定一条主要运行路径，可以使用本机工具、容器、虚拟机、浏览器或远程环境。选择必须支持实际观察任务；例如涉及内核行为、调试或硬件时，核对隔离方式和权限是否允许相应操作。不强制所有教材使用同一种工具。

环境说明至少覆盖：

- 平台与版本：适用的宿主与目标系统、必要架构、语言或编译器、运行时及依赖版本；读取第三方源码时固定版本或提交。
- 获取与搭建：工具和材料来源、安装或启动步骤、工作目录、必要配置；注明实际需要的硬件、网络、账号和权限。
- 实验材料：完整源码、输入或数据、依赖清单，以及足以复现构建和运行的命令或脚本。
- 最小自检：从准备环境到运行一个最小例子的步骤、预期结果和成功判断，附常见失败的定位方法。
- 章节对应：每项实验使用的环境、输入、命令、观察位置和判断依据；多章可引用同一份基础环境说明，仅补差异。
- 状态与恢复：记录实际验证的平台、版本、命令和结果；会改变状态的实验说明重置或清理方法，便于重做。

只要求大纲或策划时，必须给出环境方案、配套材料计划、自检方式和待验证项，并把环境准备放在首个实验之前；不因此擅自搭建或编写正文。正式交付时提供相应环境材料，并在声明环境中执行自检和相关实验。局部修改沿用已有环境，只补充或重验受影响的部分。

当前工具无法搭建或运行时，继续完成有依据的内容，明确标记“环境待搭建”或“实验待运行验证”，列出受影响的目标和接续步骤。缺少环境材料或运行验证的部分不得宣称为可完整实施的教材；静态审查不能代替实验验证。

## 组织与反馈

机制型内容可从现象和预测进入模型、执行轨迹，再改变条件。方法型内容显示关键选择和调试过程。项目型内容说明每阶段的输入、输出、依赖及可观察状态；允许读者从已有阶段继续。

示例代码、输入、输出和图必须描述同一次执行。练习可使用预测、补全、修改、诊断和独立实现，选择与当前目标对应的任务。提示逐步提供关键线索，答案解释错因，避免只给完整源码。

算法区分方案、正确性和成本。说明假设、终止、边界条件以及复杂度度量；程序测试不能代替一般性证明。引用语义、并发和数值行为按实际语言与环境检查，不将示意图当真实运行记录。

## 专业与呈现检查

按交付的搭建说明准备环境，先执行最小自检，再运行相关示例和实验，核对边界输入、正文输出及反馈。分别记录环境是否可用和实验是否符合判断依据。无法执行时明确静态审查范围及待验项。并发模拟、真实并发运行和证明分别标注。

代码换行、缩进、字符与复制结果保持可用；行号不进入复制内容。图中名称与代码对应。长清单可按教学任务拆分，并提供完整版本位置。
