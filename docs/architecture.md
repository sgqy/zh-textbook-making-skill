# 集合架构

用户按任务安装技能，编写时按学习产出选品类。七个入口分别处理研究、策划、写作、活动、审校、排版和维护；八类方法资料提供专业与媒介差异。没有额外的总调度入口，也不要求每次执行整条流程。

## 维护源与安装包

`skills/<名称>/SKILL.md` 是入口指令的维护源。`agents/openai.yaml` 只提供中文界面信息，不绑定特定 MCP 服务或关闭自动选择。标准 `SKILL.md` 可供兼容的 Agent Skills 工具发现。

`authoring/references/` 保存共用资料。`scripts/build.mjs` 将资料和根许可证复制到每个技能目录。生成副本提交到 Git，普通用户通过 `npx skills add` 下载后即可使用，不需要本地构建。

每个包包含所有品类资料，但入口只要求读取本次相关部分。重复发生在发行文件中；修改只在共用源进行。独立安装时，包内相对引用无需跨到其他技能、开发目录或特定机器路径。

构建不覆盖入口，也不自动删除未知资料。`--check` 只检查同步状态；新增、修改或缺失的生成文件使检查失败。重命名资料后，先核对并处理旧副本，避免静默丢失内容。

## 项目交接

技能组合通过教材项目的材料清单、品类决定、单元说明、活动、媒体与验证记录交接。它们不是必须各建一个文件的模板，小任务可以直接使用现有上下文。

研究区分内容依据、教法案例和可用资产；策划从材料分析作出品类与结构选择。写作、活动和审校沿用这些项目事实。排版与维护不得因格式或版本工作静默改变学习目标。

## 验证边界

自动检查保证集合可发现、独立包引用完整，以及共用资料没有漂移。它无法判断一个证明正确、一个对话自然，或读者已经学会。

行为评估将原始任务与评价依据分开。编写者自测、独立模型评估、教师审阅和真实读者观察分别记录。没有固定关键词匹配的“教学质量得分”。

历史研究支持规则选择，但不把个别教材的写法变成所有品类的默认模板。扩展子领域时先补专业依据、代表任务和合适的评价证据。
