# 编程教材写作与教学设计草稿

本稿收集可用于教材的教学方法，并提出对应的编辑动作。带“候选”字样的做法，是对研究和教材案例的转化，尚未在本项目中验证。

## 先确定读者能做什么

学习目标应描述可观察的表现，并用于选择内容、活动和评估方式。Cornell 的教学指导建议使用可观察的动作，避免只写“熟悉”“了解”等难以检验的表述。[Setting Learning Outcomes](https://teaching.cornell.edu/setting-learning-outcomes)。

候选写法：把“理解递归”改成“给定递归函数，追踪调用过程，指出终止条件，并解释为什么会终止”。随后检查：正文是否演示这些动作，习题是否要求读者独立做这些动作。

为每章建立一张短卡即可，无须扩成复杂表单：

| 字段 | 用途 |
|---|---|
| 读者已会什么 | 决定哪些解释可以省略 |
| 读完能完成什么 | 决定核心内容和练习 |
| 需要什么先修知识 | 检查目录顺序与补充材料 |
| 容易混淆什么 | 设计对照例、反例和诊断问题 |
| 用什么证明学会 | 规定任务、答案或验收条件 |

## 按知识依赖安排顺序

本轮案例支持两种可选路径。基础概念相互依赖时，可以先建立模型再应用；读者具备先修知识时，可以从任务出发，在需要时补充机制。HtDP 和 D2L 展示了不同的取舍，见[教材案例](01-教材案例.md)。

候选编辑方法：为目录标出概念首次定义、首次使用和后续复用的位置。提前使用的工具应标为暂时借用，并提供后续解释入口。技术定义不能因为追求故事流畅而被长期推迟。

贯穿案例宜复用熟悉的背景，并逐次增加目标相关的复杂度。与本节目标无关的登录、部署或界面配置，可以移入准备材料。这个取舍应逐章判断，不设固定的新概念数量。

## 示例要显示决策过程

NCCE 的编程教学资料强调：完整或部分完成的示例可支持初学者；可以标注子目标，将示例与相似练习交替，并逐渐减少帮助。资料还区分了只给结果的示例和展示求解过程的示例。[Using Worked Examples，第 1 页](https://media.teachcomputing.org/QR_2_Worked_examples_fd8c8f5064.pdf)。

候选示例结构是：先给任务和约束，说明为什么选择这种表示或算法，展示关键步骤，再检查结果。注释应解释决策，例如“保留旧值，避免后续计算读到更新后的状态”；不要逐行翻译语法。

完整代码、教学片段、伪代码和故意错误的代码应明确区分。故意错误的示例紧接失败条件、观测结果和修正理由。教学片段应注明省略范围，并提供完整上下文的位置。

## 练习承担不同的学习任务

IES 的 2007 年指南将间隔学习、例题与独立解题交替、图文结合及连接具体与抽象表征列为中等证据支持的建议；将通过测验再次接触关键内容、提出深入解释问题列为强证据支持的建议。这里沿用该指南的评级，不把它解释成针对编程教材的最新统一评级。[IES 指南及证据表](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。

计算教育中的 PRIMM 提供另一种活动顺序：预测、运行、探究、修改和创造。NCCE 也建议安排读代码和追踪活动。其指导主要面向学校计算教育，成人自学教材需要调整节奏和题材。[NCCE 教学原则](https://teachcomputing.org/pedagogy)。

以下题型是据此提出的候选组合，不要求每章全部使用：

| 题型 | 示例任务 | 核验重点 |
|---|---|---|
| 预测 | 运行前写出输出或状态变化 | 是否有理由，是否能定位第一次偏差 |
| 补全 | 补齐一个边界条件或数据变换 | 是否知道缺失部分的作用 |
| 修改 | 改变输入限制，并调整程序 | 是否识别原方案依赖的假设 |
| 解释与比较 | 比较两种方案适用条件 | 是否使用正确的模型与指标 |
| 独立迁移 | 在新情境中应用本章方法 | 是否仍依赖原例的表面细节 |
| 延后回顾 | 后章再次使用前章概念 | 是否能在间隔后提取并应用 |

每道练习应有与目标对应的反馈。自学书可分开提供提示、关键思路和完整解答。设计题允许多种答案时，应给评价依据；程序题应覆盖边界条件；实验题应区分确定输出与允许波动的指标。

## 解释容易误解的地方

候选做法是为关键概念写一个最小对照例。例如，解释“同名变量”和“同一存储位置”的区别时，用两个仅改变绑定关系的例子。读者应能指出哪个变化导致哪个结果。

类比之后应回到真实模型，并说明类比失效的位置。图解也需要指出抽象层次：内存图中的方框表示变量、对象还是地址区间，必须前后一致。

章节末尾可回答“现在能解释什么”“哪些条件下不能使用本章方案”“下一章需要解决什么”。无需逐节重述刚讲过的内容。

## 技术正确性与教材维护

以下为工程编辑候选规则，不属于已验证的教学效果结论：

- 可运行示例记录语言、依赖、平台和运行入口；在记录的环境中验证。
- 把正文展示的代码与可执行代码关联，避免手工复制后逐渐分歧。
- 对边界条件、错误处理和关键假设提供说明；简化代码应说明简化了什么。
- 概念与短期工具操作分开维护。依赖更新时，定位受影响的代码、截图、练习和答案。
- 性能结论记录输入规模、测量方法与环境。随机实验给出容差或趋势，避免要求逐字匹配输出。

最优的练习数量、章长和示例密度不能从这些来源直接推出。下一步应写一章样稿，观察目标读者在哪些位置停顿、误解、查阅前文或无法独立完成任务，再调整这些参数。
