# 编程与计算机教材编写 skill 候选规则

本稿把研究结果转化为可试用的指令。它是正式 skill 的设计输入，尚未安装，也未通过实际写章任务验证。

后续已扩展为跨品类的多技能集合规划。本文保留编程分支的教学方法候选，不再规定整个集合的范围或统一流程。技能职责与实施阶段见[技能集合设计](../../planning/01-技能集合设计.md)和[成果与验证计划](../../planning/02-成果与验证计划.md)，新增流程见[材料分析与品类选择](../../planning/03-材料分析与品类选择.md)。

## 预期能力与边界

本稿的方法候选面向用中文讲解的编程与计算机教材，支持选题、目录、样章、练习、解释质量和版式设计。不扩展为多语种教材编写或翻译工具；教学对象、术语、代码等必要原文按内容需要保留。它应能处理“写一节”“审一章”和“规划一本书”等不同粒度的请求。普通问答或 API 查询无需启动完整教材流程。

最少需要知道读者基础、学习目标、技术范围和输出载体。已有上下文能确定的内容直接采用；缺失信息只有在会改变选材或结构时才询问。用户只要求修改一节时，不扩成整书重写。

## 候选工作流程

1. 明确本次交付及读者任务。学习目标采用可检查的动作。
2. 查清先修知识，标出必要定义、示例和练习的关系。
3. 根据目标选择章节模式，写出能代表全书难点的样章。
4. 核验技术事实、代码、推导和答案，并记录未能验证的部分。
5. 在目标载体中检查代码、图表、公式和交叉引用。
6. 根据读者实际表现修订；保留修订依据。

这是可裁剪的流程。改一个术语无需重新规划目录；纯文字草稿也无需先构建完整出版系统。

## 哪些规则值得优先试用

| 条件 | skill 应执行的动作 | 产出或检查证据 | 依据 |
|---|---|---|---|
| 新写章节 | 把目标写为可观察任务，并检查正文和习题是否支持目标 | 简短目标与任务对应关系 | Cornell 学习目标指导，见写作草稿 |
| 面向初学者 | 展示关键决策过程；安排适量补全或修改，再转向独立任务 | 示例、提示与后续练习 | NCCE 示例指导 |
| 引入抽象 | 给出能展示共同结构的具体实例，并解释抽象保留了什么 | 实例与抽象之间的对应说明 | SICP 案例；本研究推论 |
| 比较机制或方案 | 明确假设和指标，用反例说明适用边界 | 可复算的对照 | OSTEP 案例；本研究推论 |
| 采用贯穿项目 | 提供组件接口、验收条件和可继续学习的起点 | 章节项目卡及依赖入口 | Nand to Tetris 案例；本研究推论 |
| 包含代码 | 标明完整程序、片段、伪代码或错误示例；验证承诺可运行的部分 | 环境、入口及实际验证结果 | 工程编辑建议 |
| 包含数学推导 | 定义符号，说明每一步成立条件，关联代码或实例 | 符号与变量对应、数值检查 | D2L 案例；本研究推论 |
| 输出数字教材 | 保留语义结构；为复杂图补充必要的文字说明 | 阅读顺序与图像说明检查 | W3C WAI 指导 |

来源与限定条件集中在[写作草稿](02-写作与教学设计.md)、[排版草稿](03-排版与阅读设计.md)和[教材案例](01-教材案例.md)，避免在正式指令中重复大段研究材料。

## 可选章节模式

| 模式 | 适用任务 | 可用顺序 |
|---|---|---|
| 问题与机制 | 操作系统、网络、数据库等机制解释 | 现象、假设、模型、推演、反例、边界 |
| 程序设计 | 初学者学习构造程序 | 问题、数据表示、输入输出实例、设计、实现、测试 |
| 抽象形成 | 学习复用与一般化 | 具体实例、共同结构、抽象、应用、限制 |
| 系统构建 | 用若干模块完成一个系统 | 本章接口、设计、实现、测试、组合 |
| 数学与实验 | 算法和机器学习中的模型理解 | 问题、符号、推导或模型、实现、结果解释 |

这些顺序是选择提示，不是强制标题。可以组合、删减或调整，但应说明调整服务于哪个学习目标。

## 原创微型样稿：先确定二分查找的边界

下面是本研究自拟的片段，用于检验候选规则。它没有改写某本教材的例题。

### 目标与问题

你将用一个始终成立的条件解释二分查找为何不会丢失候选位置。假设数组已经升序排列，任务是找到第一个大于或等于目标值的位置；找不到时返回数组长度。

数组为 `[2, 5, 9, 12, 18]`，目标值为 `10`。答案是下标 `3`，因为 `12` 是第一个满足条件的元素。

### 用区间记录尚未确定的部分

使用半开区间 `[lo, hi)` 表示尚未分类的元素。初始时 `lo = 0`，`hi = 5`。

保持两个条件：下标小于 `lo` 的元素都小于目标值；下标大于或等于 `hi` 的数组元素都大于或等于目标值。

取中点 `mid = 2`，该位置的值为 `9`。由于数组有序，下标不大于 `2` 的元素都小于 `10`。因此可以令 `lo = 3`，继续搜索 `[3, 5)`。

### 预测与检查

在继续之前，判断下一步是否可以直接返回下标 `4`。说明你还需要排除哪个位置。

提示：目前只能确定答案不会小于 `3`。还需要比较剩余区间中的元素。答案是下标 `3`；一次缩小区间不等于已经找到第一个满足条件的位置。

### 后续练习

把目标改为 `19`，解释为什么返回 `5`，以及为什么不能读取数组的下标 `5`。再考虑空数组：没有可读取元素时，返回值应是多少。

### 编辑备注

完整小节还需补充更新两端边界的规则、终止理由、实现和测试。测试至少覆盖空数组、重复值、目标小于全部元素和目标大于全部元素。这里仅示范问题、模型、推演和反馈的衔接，不把片段标为完整教学单元。

## 不宜固化的要求

- 每章固定字数、概念数、例题数或习题数。
- 每节必须包含故事、问答、图示或完整项目。
- 一律先实践后理论，或一律先定义后例子。
- 把某部名著的章节顺序当作所有读者的默认路径。
- 为了维持章节格式，加入与目标无关的练习或重复说明。

## 正式 skill 的候选结构与验证

入口只保留任务识别、关键判断和必要检查。教材模式、练习设计、排版细节和样例可按需放入参考文件。只有出现重复的确定性工作后，再增加代码提取、交叉引用检查等脚本。

建议先用三类实际请求试写：面向初学者的变量与状态、面向有经验程序员的并发、带数学的算法分析。观察是否有先修缺口、伪造验证结果、形式化套模板或答案泄露过早等问题。

随后请目标读者完成指定任务，记录错误类型与求助位置。根据结果决定哪些候选规则保留，哪些应降为可选提示。文件格式验证只能检查 skill 结构，无法代替这一步。
