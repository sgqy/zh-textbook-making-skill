# musl 教材策划试用产出

本方案面向有编程经验、具备一定 C 基础的读者，选择“编程与计算机 / 机制理解与源码分析”。目标是让读者从程序现象定位 musl 实现，区分语言接口、库行为与内核职责，并用实验核对解释。

现有材料足以规划启动、系统调用、标准 I/O、内存和线程的学习顺序。具体调用路径与实验输出仍需对固定源码逐章核验。本轮只交付策划，不安装、下载、构建或运行。

## 必备实验环境方案

主要路径选为 Windows 宿主上的独立 Linux x86-64 虚拟机。编辑、构建、调试与实验均在虚拟机内完成。正式教材须交付环境说明和实验文件，不能仅凭平台名称认定读者已能复现。

| 项目 | 方案与待定条件 |
|---|---|
| 宿主与目标 | 宿主为 Windows；目标为 Linux x86-64。虚拟化工具、Linux 发行版及镜像版本尚待选定，届时记录官方获取地址与镜像校验值。宿主架构和虚拟化支持需确认。 |
| 教学源码 | 沿用输入指定的 musl v1.2.6；实施时核对源码来源，记录对应提交或归档校验值。本轮没有获取源码。 |
| 构建与观察工具 | 计划使用 C 编译器、make、二进制查看工具、GDB 和 strace；选定发行版后锁定实际工具版本及安装命令，并记录内核版本。 |
| 工作目录 | 计划在虚拟机用户目录下分开存放源码、构建、独立安装前缀、章节实验与结果。教学构建安装到独立前缀，便于确认使用了目标 musl。 |

| 恢复 | 准备基础环境快照；每章结果写入独立目录。正式脚本须限制清理范围，保留读者修改的源码。 |

搭建顺序计划为：创建虚拟机并核对架构 → 安装固定工具版本 → 获取并校验教学源码 → 在独立目录构建和安装 → 执行最小自检 → 开始章节实验。下一阶段应将这一路径整理成可照做的步骤。

拟交付文件如下。这些是材料计划，目前均未创建：

- `environment/README.md`：宿主条件、镜像获取、搭建步骤、工作目录、权限、自检和常见失败处理。
- `environment/versions.txt`：源码提交、镜像校验值、系统、内核与工具版本。
- `tools/build-musl.sh` 与 `tools/check-env.sh`：构建安装和最小自检的执行入口，写明调用目录与参数。
- `labs/`：各章完整源码、输入文件、构建与运行说明、观察任务和重置方法。
- `checks/`：判断依据及真实运行记录；不预填尚未取得的输出。

## 最小自检计划

1. 记录目标架构、内核和工具版本，检查文件路径与权限。工具缺失或架构不符时停止后续实验，给出对应修正入口。
2. 构建一个最小的静态程序。检查构建记录及二进制信息，确认使用了教学 musl 的头文件、启动文件和库。
3. 运行该程序。预期打印约定文本并正常退出；这是判断标准，尚不是实测输出。
4. 为涉及动态链接的章节补动态程序自检，核对解释器路径和库的来源。动态程序失败时先查目标解释器和安装位置。
5. 确认调试器能命中选定源码位置、系统调用跟踪工具能记录所需事件。不能调试或跟踪时，该类观察任务保持待验。

环境自检通过只说明相关工具和最小程序可用；每章仍需运行自己的实验并核对结果。

## 目录与实验依赖

| 章 | 主要内容 | 任务与判断依据 |
|---|---|---|
| 1．实验环境与阅读方法 | 完成环境准备、自检、源码导航；区分预测、源码依据和运行证据 | 建立版本记录，完成最小程序与观察工具自检。此章先于其他实验。 |
| 2．musl 的职责与 C 补充 | C、POSIX 和 Linux 的边界；对象、指针、整数转换、生命周期与未定义行为 | 分析短例，指出结论依赖的接口约定与语言条件。 |
| 3．构建、链接与程序启动 | 编译和链接产物；静态程序进入 main 前后的工作 | 复用基础环境，跟踪启动与退出，提交标明来源的执行顺序。 |
| 4．系统调用与错误处理 | 库接口、调用封装、返回值及 errno | 对成功和失败调用记录输入、返回值与跟踪结果，解释转换关系。 |
| 5．标准 I/O 与缓冲 | 文件描述符、流状态、缓冲、刷新及错误 | 让同一程序分别写向终端、文件与管道，记录输出和调用轨迹。实验需提供输入、运行方式及结果判断。 |
| 6．内存分配 | 分配接口、对象生命周期、分配与回收路径 | 跟踪一组分配操作，结合源码解释状态；实验结果按实际版本核对。 |
| 7．线程及同步 | 创建与退出、线程局部状态、锁与等待 | 观察受控线程场景，区分一次运行轨迹与一般并发正确性论证。 |
| 8．综合诊断 | 从现象缩减复现，形成可核查的解释 | 使用已有实验环境提交最小程序、版本、运行方法、证据及结论范围。 |

第 1～2 章建立共同基础，第 3～5 章积累跟踪方法，再进入内存与线程。暂缓其他架构、完整动态加载器、网络和数学库，避免超出当前材料范围。

样章选择第 5 章：先预测输出行为，再在不同输出目标下观察，阅读相应缓冲路径，最后改变条件做独立诊断。反馈应说明证据支持哪些判断，以及哪些现象仍需要补充实验。
